# Java10143 后端上云部署指南（Render + TiDB Serverless，免费）

> 目标：把 Spring Boot 后端 + MySQL 搬到云上，朋友用移动数据也能稳定访问（根治隧道慢/会变）。
> 费用：**0 元**（Render 免费层 + TiDB Serverless 免费额度）。代价：国内访问略慢、免费层可能休眠。
> 隐私：数据库密码、JWT 密钥**只存在于云控制台的环境变量里**，绝不进代码 / Git / 镜像。

## 三、在 TiDB 建库 + 脱敏初始化（关键隐私步骤）

**绝不导入** `sql/java10143.sql`（含真实手机号、密码 MD5 哈希，已被 .gitignore 排除）。

1. TiDB 控制台创建数据库：`CREATE DATABASE java10143 CHARACTER SET utf8mb4;`
2. 初始化**只导入展示所需的表与脱敏数据**。需要一份“仅商品/分类/演示账号”的脱敏脚本：
   - 由阿布从现有 SQL 中抽取**商品表、分类表**并脱敏（手机号留空/打码、密码统一用已知演示 MD5），生成 `deploy/seed-safe.sql`。
   - 或你本地用 `tools/make-clean-zip.py` 思路自行脱敏后导出。
3. 把生成的 `deploy/seed-safe.sql` 在 TiDB 控制台 / `mysql` 客户端执行。

## 四、在 Render 创建 Web Service

1. Render 控制台 → **New** → **Web Service** → 关联你的 GitHub 仓库。
2. 它会自动识别 `render.yaml`；确认：
   - Runtime: Java
   - Build Command: `./mvnw clean package -DskipTests || mvn clean package -DskipTests`
   - Start Command: `java -jar target/Java10143.jar`
3. 在 **Environment** 里填写 `sync:false` 的那几项（render.yaml 里标记了，控制台会提示）：
   - `SPRING_DATASOURCE_URL`：TiDB 控制台给出的 JDBC URL，形如
     `jdbc:mysql://<host>:4000/java10143?user=<user>&password=<pwd>&sslMode=VERIFY_IDENTITY&enabledTLSProtocols=TLSv1.2,TLSv1.3&useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true`
   - `SPRING_DATASOURCE_USERNAME` / `SPRING_DATASOURCE_PASSWORD`：TiDB 的
   - `JAVA10143_JWT_SECRET`：本地执行 `openssl rand -hex 32` 生成的随机串
   - `JAVA10143_PUBLIC_URL`：部署完成后的 Render 域名，如 `https://java10143-backend.onrender.com`
4. 点 **Deploy**。免费层首次构建较慢（Maven 下载依赖），等几分钟。
5. 部署完成后，Render 给一个域名 `https://java10143-backend.onrender.com`，把它回填到上面的 `JAVA10143_PUBLIC_URL` 并重新部署一次（让服务自身地址正确）。

## 六、前端指向云后端（让 H5 / APK 也能用数据）

后端地址变成 `https://java10143-backend.onrender.com` 后，前端要把 API 基址改过去：

- **H5**：`uni-app/pages/index/index.vue` 里 H5 端的 `adminBase` 现在生产环境是 `''`（同源）。需改成云后端地址，或引入 `VITE_API_BASE_URL` 环境变量统一管理（H5 打包时注入）。
- **APK**：同理，打包前把后端地址写死/配置为云地址，再重新云打包。
- 改完重新编译 H5 / 重新打包 APK，朋友用移动数据就能稳定打开、数据也通。
